### 12:25–12:30 Hook regex incident
First pre-commit hook used bare `claude|anthropic` pattern which blocked
legitimate OpenRouter model IDs in commit bodies. Also used
`pre-commit` for message checks, but pre-commit cannot see the commit
message — git does not hand it to pre-commit. Reading
`.git/COMMIT_EDITMSG` returns a *stale* copy from the last failed
attempt, which causes confusing loops where new messages are
rejected because the file still holds old trigger phrases.

Fix: split into `pre-commit` (scans staged diff) + `commit-msg`
(git passes the message-file path as arg 1). Narrowed message regex
to attribution *phrases* only (coauthor trailers, generator/assistance
markers, the robot emoji, the tool name) so provider names as model
IDs continue to work in commit bodies.

commits: `46bd0a2` (reverted by split), `5fb80d6 chore(hooks): split
message check into commit-msg hook`

### 12:35–12:50 OpenRouter client
`src/utils/openrouter.py`. Three design calls worth recording:
1. **Cost from API response, not hardcoded pricing.** OpenRouter's
   `usage.cost` field is populated per call. Maintaining a local
   price table means churn every time a provider adjusts; reading the
   response is strictly more accurate.
2. **Determinstic hash key for diskcache.** `_hash_request` sorts
   dict keys via `orjson.OPT_SORT_KEYS`, so rerunning the same
   generation script at the same seed hits cache and costs 0 USD.
3. **Budget as a separate JSON ledger with a lock.** The ledger is
   process-independent and persists across runs. `check()` before
   sending, `record()` after.

Smoke test: `claude-haiku-4.5` returned `"hi"` at USD 3.1e-05.
Budget ledger updated correctly.

commit: `adb714d feat(utils): OpenRouter client with budget guard,
cache, and call log`

### 12:50–13:00 Utterance pipeline
`timeline.py` is deterministic — seed 42 produces 32/39/38 events for
yejin/minseok/sunhee across 60 days. Each event has
`links_back_to_day` and `links_back_historical` so later utterances
can reference them; those links become retrieval gold labels once
scenarios are built (Day 2).

`utterance_gen.py` does one LLM call per `(persona, day)`, generating
a JSON object of 12 utterances with `intended_topics` and
`references_historical_event`. Round-robins G1/G2/G3 with
normalized weights; consecutive days draw different generators.
G4 Kanana is deferred (it's local HF, Apache-2.0 constraint, per
`DATASET §4.1`) — its 20 % share is folded into the three API
generators for Day 1.

Two parse bugs caught in smoke test:
- Gemini 2.5 Pro truncated at `max_tokens=2000`. Bumped to 4000.
- Claude Sonnet 4.5 on OpenRouter returned text that `response_format`
  did not strictly box as a JSON object. Switched strategy to
  prompt-level JSON instruction + regex extraction of the first
  `{...}` block + markdown-fence stripping. Works for all three.

Smoke test (yejin, 2 days, 8/day): 16 utterances, USD 0.0381.
Extrapolation to full run: ~USD 3.9 for 180 calls. Budget cap set to
USD 8.0 for headroom.

commit: `54de4e1 feat(datagen): timeline + utterance generator with
G1/G2/G3 rotation`
