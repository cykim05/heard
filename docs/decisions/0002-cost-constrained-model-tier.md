# ADR 0002 — Cost-Constrained Model Tier

## Status
Accepted (2026-04-23)

## Context

`configs/models.yaml` originally used the frontier tier:
- Generators: Claude Sonnet 4.5, GPT-4o, Gemini 2.5 Pro
- Judges: GPT-4o, Claude Opus 4.6

Budget cap is USD 30 total. Full-project projection at the frontier
tier:

| Phase | Projected |
|---|---|
| Day 1 utterance corpus (180 calls) | ~4 |
| Day 2 Track B translation | ~2 |
| Day 2 Track C scenarios | ~3 |
| Day 3 Judge sweep (16K judgments × GPT-4o) | ~10 |
| Retries & validation | ~2 |
| **Total** | **~21** |

~70 % of that is the Day 3 judge sweep. The project owner asked for
a firm cheaper cap — so the frontier tier is not justified for this
workload.

## Decision

Switch every OpenRouter model to its small/flash variant:

| Role | Was | Now |
|---|---|---|
| G1 | `anthropic/claude-sonnet-4.5` | `anthropic/claude-haiku-4.5` |
| G2 | `openai/gpt-4o` | `openai/gpt-4o-mini` |
| G3 | `google/gemini-2.5-pro` | `google/gemini-2.5-flash` |
| G4 | `kakaocorp/kanana-1.5-8b` (local) | unchanged |
| J1 | `openai/gpt-4o` | `openai/gpt-4o-mini` |
| J2 | `anthropic/claude-opus-4.6` | `anthropic/claude-haiku-4.5` |

Per-item judge exclusion (DATASET §4.1) still holds: if an item was
generated by the GPT-4o-mini family route it to J2 (haiku), and if
generated by haiku route it to J1 (mini). Gemini-flash and Kanana
can use either judge.

New projection:

| Phase | Projected |
|---|---|
| Day 1 utterance corpus | ~0.7 |
| Day 2 Track B translation | ~0.5 |
| Day 2 Track C scenarios | ~0.8 |
| Day 3 Judge sweep | ~1.2 |
| Retries & validation | ~0.5 |
| **Total** | **~3.7** |

Sunk cost from the initial frontier run: **USD 0.75** (18 days of
yejin utterances already cached under the old model IDs). Those
cache entries are keyed on model, so they are unused going forward
but do not need to be deleted.

## Consequences

- Utterance quality may drop noticeably — Haiku 4.5 and GPT-4o-mini
  produce less nuanced Korean. We need to re-read the first 20
  utterances of yejin and compare against the frontier samples
  saved in `experiments/_parse_failures/` before committing to the
  new corpus as final. If quality is clearly degraded, selectively
  upgrade G1 back to Sonnet for yejin (the persona that carries the
  main case study).
- Judge discrimination on the reflective-quality pairwise task may
  be less reliable. Mitigation: the two-judge agreement check (r >
  0.7, §9.2) is our guardrail — if the cheaper judges diverge, we
  escalate the failed items to Sonnet.
- All earlier run logs in `experiments/_api_log/api_calls.jsonl`
  remain valid; filter by `model` field when computing any
  quality-vs-cost analysis for the report.
- Risk of hitting each model's individual rate limit is higher on
  flash tiers. Tenacity retry plus 0.3 s inter-call sleep already
  in `scripts/01_generate_data.py` should hold.

## Alternatives considered

- **Keep Sonnet only for utterance generation**, cheap elsewhere.
  Saves ~USD 3 in corpus cost but loses ~USD 7 in judging
  anyway. Not the dominant term.
- **Reduce `--per-day` from 12 to 8.** Saves 30 % on corpus but
  weakens retrieval haystack density. Rejected.
- **Cut scope to 2 personas × 40 days.** Saves more but undermines
  the "schema transfer across 3 personas" claim. Rejected.
